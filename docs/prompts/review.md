# フォルダの見直しの作業の指示文（UIUX U8）

フォルダの作業がすべて終わったとき（バックログに待ち・動作中が無く、依頼にそのフォルダの未完了〈new・asking・routed〉が無く、
しばらく〈60 秒〉そのまま）に、アプリ（`src/main/review.js`）が自動で積む見直しの作業の本文。下の ```text のブロックの中身だけが使われる（ほかの行は説明）。

- 見直しは、振り分けた作業と同じに、そのフォルダのセッションで動く（前置き docs/prompts/routed-session.md と「この作業の id」が付く）。
  見つけたものは、前置きの「次にやること（propose）」で `.bantodesk/outbox/` に出す（U7、docs/plan-propose.md）。
- 置き換える印: `{{folder}}`（フォルダの絶対パス）、`{{name}}`（フォルダ名）、`{{round}}`（続けて何回目か）、`{{max}}`（続けての上限、3）、
  `{{requests}}`（依頼でそのフォルダに来たユーザーの原文。PMO が直す前の文。新しい 10 件まで）。
- 見直しで何も出なければ、アプリがそのフォルダに「すべて完了」の印を付ける（ダッシュボードのカード・projects.json の review）。
  出たものが振り分けられて終わったら、もう一度見直しを積む（続けて 3 回まで。超えたら PMO に知らせ、ユーザーの判断にする）。
- 起動のたびに読み直す（このファイルを直せば、次の見直しから効く）。読めないときは `src/main/review.js` の `REVIEW_FALLBACK`。
- PowerShell 経由の起動で壊れないよう、ダブルクォートは使わない（指示文は claude の入力に送られるが、前置きと同じ決まりにそろえる）。

```text
フォルダ {{name}}（{{folder}}）の作業がすべて終わったので、アプリが見直しの作業を積みました（続けて {{round}} 回目。{{max}} 回まで）。
この作業の目的は、ユーザーの目的に照らして成果が最善になっているかを確かめ、次にやる作業が残っていないかを洗い出すことです。新しい機能を自分で作り始める作業ではありません。

やること:
(a) フォルダの README、PLAN / project-plan（あれば docs/roadmap.md などの計画）、PROGRESS.md と、下のユーザーの依頼の原文を読み、ユーザーの目的を自分の言葉で 3〜5 行に書き直す。
(b) 成果物を目的に照らして確かめる。動かせるものは動かし、開けるものは開き、数字は検算する。テストがあれば打ち切り時間を付けて回す。見るだけで分からないものは、確かめた方法と結果を書く。
(c) 足りないもの・直すべきもの・目的からずれているものがあれば、次にやること（propose）として作業フォルダの .bantodesk/outbox/ に出す（書き方は前置きのとおり: .bantodesk/outbox/review-1.json のような名前の JSON に、type は propose、title、text〈新しいセッションがそれだけで作業できる指示文〉、reason〈目的のどこに足りないか〉、from〈この作業の id〉。一度に 5 件まで）。自分では始めない。小さな書き漏れ（PROGRESS.md の状態のずれなど）だけは、ここで直してよい。
(d) 何も無ければ、最善と判断した理由（目的の各点と、それを満たす成果物・確かめた結果の対応）を返答に書き、PROGRESS.md の表に 「すべて完了（見直し済み）」 の行を足す（状態は 完了、次の一手は —、更新日は今日）。PROGRESS.md が無ければ作らずに、返答に書くだけでよい。
(e) 最後に 作業完了 と書く。

ユーザーの依頼の原文（PMO が直す前の文）:
{{requests}}
```
